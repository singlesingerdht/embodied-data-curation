# 算法接入与内化

[English](ALGORITHM_INTEGRATION.md) · [插件开发](ALGORITHM_PLUGIN.zh-CN.md) · [输出接口](../reference/OUTPUTS.zh-CN.md)

本文说明算法开发者如何通过插件接入 EDC，以及如何将算法实现纳入框架维护。
提交内容包括实现、输入输出说明、依赖与来源、使用示例及测试。

## 1. 选择类别与代码位置

算法类别描述用途；内置或插件描述代码归属和加载方式。外部算法先通过插件交付，
验证后可纳入框架，也可继续独立维护。内部自研算法可以直接按目录约定开发，接受同等验证。

| category | 用途 | 必须保留的输出 |
|---|---|---|
| quality | 检查缺陷及数据是否满足要求 | 原生指标、分项判断、覆盖范围及证据 |
| value | 评估覆盖、分布、贡献或指定实验中的价值 | 原生统计、事件、评分或估值及适用实验 |
| editing | 修复、裁剪或调整既有数据 | 新数据、params、source_mapping |
| augmentation | 增加样本或生成变化版本 | 新样本、params、source_mapping |

内置算法的目录归属约定如下，路径相对仓库根目录：

```text
src/edc/algorithms/
├── registry.py
├── contracts.py
├── quality/algorithms/<Algorithm_Name>/
├── value/algorithms/<Algorithm_Name>/
├── augmentation/algorithms/<Algorithm_Name>/
└── editing/algorithms/<Algorithm_Name>/
```

**当前加载边界：** 核心内置发现通过现有质量适配器加载九项质量算法，尚不支持上述四类目录的
统一自动发现。其他类别可通过插件接口接入；仅创建目录不会完成注册，也不能据此宣称算法可用。

内置实现以 `algorithm.py` 提供轻量声明和执行入口，计算模块按实际需要组织为
`method.py`、`extractor.py`、`metrics.py` 等文件。附上 `README.md` 和可追溯的 `SOURCE.json`，
说明作者、源码来源、许可证、输入输出、参数、可用依赖和限制。只有实际复用的代码才提取到
类别的 `shared/`；数据读取、执行和工作流复用框架现有能力。

## 2. 实现统一接口

内置与插件共用 `AlgorithmSpec + run(context, params)`，由框架执行预检、参数校验和结果保存。
外部安装插件通过 `edc.algorithms` entry point 发现，`EDC_PLUGINS` 目录入口同样遵守插件校验。
可运行的外部插件示例见[插件开发](ALGORITHM_PLUGIN.zh-CN.md)。

- 内置 ID 与算法目录名一致；外部 ID 使用 `team__algorithm`。ID 在整个注册表中唯一，
  重复 ID、接口版本不兼容和非法声明明确失败，不静默覆盖。
- 粒度为 `episode` 或 `dataset`。数据集算法实现 `preflight_dataset(dataset, params)`，
  对选定数据集执行一次；逐轨迹筛选使用 `episode_requirements/preflight_episode`，
  不混填仅适用于 episode 算法的输入声明。
- 声明与发现阶段不得导入模型库、初始化模型或下载权重；依赖和设备条件在预检检查，模型在执行时加载。
- 使用 Dataset → Episode → Channel，保留稳定 ID、source、selector、单位、时间来源和 clock。
  输入只读，输出写入 `context.workdir`，不另建源目录旁的缓存。
- 原生结果按[输出契约](../reference/OUTPUTS.zh-CN.md)保存；处理失败与数据判断独立。
  价值分数不自动生成质量结论，不生成跨算法总分。
- 内部代码直接导入所属模块；外部插件通过 `edc` 公共入口使用公共类型。

## 3. 将插件内化为内置实现

1. **准备比较基线。** 固定源码、有效参数、输入与 selector、依赖和模型权重；
   有未提交修改时记录文件哈希，不能仅以提交号代表当前实现。基线结果只读保留。
2. **确定目标与版本。** 按类别选择目录，明确旧/新 ID，分别记录方法、接口与包版本。
   纯搬迁保持方法和接口版本；计算含义、阈值或 clock 行为变化应单独评审和验证。
3. **迁移单一实现。** 一并迁移方法、适配、来源声明、必要资源和测试，删除对研究环境路径的依赖。
   接入统一注册能力；若目标类别尚无内置发现，先补齐对应支持并验证。不得为新算法增加核心按 ID 分发分支。
4. **更新当前调用。** 更新参数键、工作流、机器人 checks、示例及测试中的算法 ID。
   保持质量预设和报告顺序；价值算法不因内置而加入质量预设。历史 run/catalog 不改名。
5. **退役旧入口。** 在目标环境停用该算法原 entry point；插件中的其他算法继续保留。
   即使旧/新 ID 不同，也需检查旧入口残留；两份实现仍可执行时不能判定切换成功，不添加静默别名。
6. **验证后更新使用说明。** 核对安装包和新运行结果，仅说明实际可用的入口、参数、依赖及限制。
   每次对照使用独立输出目录，不覆盖历史结果。

## 4. 验证接入与内化

- **接口与失败处理：** 覆盖安装发现、正常执行、缺输入、缺依赖、坏样本、部分失败、
  重复 ID 和不兼容接口。插件导入失败需保留诊断且不阻塞其他插件；目标缺失仍属于接入失败。
- **结果等价性：** 相同输入、selector、有效参数、权重、随机种子及依赖下比较稳定 ID、
  通道/时间来源、原生分数/事件/分布、完整性和失败语义。确定性结果逐字段一致；
  模型非确定性或浮点容差在运行前确定，不为通过而事后放宽。允许变化的运行 ID、耗时、
  输出位置和预期算法 ID 应提前列明。
- **模型与范围：** 固定数组或推理替身验证契约和统计，真实模型另行验证；
  接口通过不能代替检测效果、多数据集适用性或训练收益。未检查与未完成需明确表示。
- **安装包：** wheel/sdist 包含方法和 SOURCE 等资源；在源码树外安装，核对实际导入位置、
  唯一注册和最小执行。基础安装不要求模型/GPU依赖，缺少执行依赖时明确报错。
- **编辑与增强：** 验证 output、params、source_mapping 和新数据质量复检。
  当前通用工作流仅支持行数、时间不变的 identity 映射；裁剪、重采样及新合成轨迹需另行实现和验证。
- **来源与许可：** 分别核查算法代码、第三方库、模型和数据。未确认许可不能声明具备公开发布授权。

## 5. 切换失败时恢复

保留诊断证据，恢复本次内化对应的旧插件、配置和依赖环境，只撤回本次迁移改动。
新旧结果分别保存，不重命名旧 catalog 冒充新运行，不覆盖原始数据或其他开发工作。

复验通过后再更新使用说明，确保文档中的算法入口和安装包实际可发现的实现一致。
