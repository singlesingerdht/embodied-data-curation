# 所有读取入口的单位、语义与时间边界

本页说明读取端、配置端、算法端与报告端各自负责什么。不是新算法或新数据文件格式。
原始数据只读，不清洗、不补值、不改采样频率；已有算法公式、评分与阈值保持不变。

## 接口归属与本次兼容边界

| 端 | 输入 | 输出／责任 | 本次变化 |
|---|---|---|---|
| 使用者的机器人配置 | 源字段、逻辑名、字段级单位、物理量、指令／反馈、坐标系、时间来源与时钟 | 描述真实数据，未知项保留未知 | 不新增必填公共 API；HDF5／Parquet／轨迹 JSON 的原时间单位未填、null、空串、unknown 统一视为未知，不再默认秒 |
| 读取器 | 原文件与机器人配置 | Dataset → Episode → Channel、原数值、图像入口、原始时间及来源 | 数值源读取不再统一强转 float64；保留可表达的原始整数／浮点类型，布尔接触状态不变成力值 |
| 算法执行视图 | 字段级源单位与原数值 | 支持的物理量按 SI 读取，并记录换算；不能换算则阻止物理算法 | 字段级 quantity／semantic_status 可覆盖通道声明，明确未确认时不能被通道级 confirmed 掩盖 |
| 算法参数 | channels、检测参数及必要标定 | 选择已登记数据；物理阈值采用算法要求的 SI | 不调整公式、评分或默认阈值 |
| 结果与报告 | 执行状态、数值、覆盖与源映射 | 区分格式可读、算法可执行、评估完整与质量达标 | time_evidence 增加实际时间单位来源与不可用原因；旧记录不改写 |

旧配置若真实存的是秒，补上 timestamp_unit: s 即可恢复相应单路时间检查；不能为了运行算法而猜填。
ROS／MCAP 的已定义整数纳秒不受此变化影响。LeRobot 标准 timestamp 按格式规定是秒制索引时间，
不靠用户重填单位；兼容读取器会拒绝把这一标准列声明为 ms 等其他单位。自定义原时间必须另选原时间列。

## 不同数值与模态分别处理

| 数据 | 配置至少要说清 | 已有读取／换算边界 |
|---|---|---|
| 机械臂、灵巧手、头部关节 | 部位、左右、顺序、转动还是伸缩、指令／反馈 | 转角 deg → rad；伸缩 mm／cm → m。不能把所有 position 都当角度，也不能把灵巧手称为夹爪 |
| 关节速度与加速度 | 物理量与字段级单位 | deg/s → rad/s；deg/s^2 → rad/s^2。不从字段名 velocity 猜成速度或加速度 |
| 末端位置与姿态 | XYZ 单位、坐标系、旋转表示、分量顺序 | mm → m；四元数声明 unit: '1'，保持分量和顺序，不转弧度；欧拉角须有明确布局和角度单位 |
| 电流、力和力矩 | 每个字段的物理量、来源、单位及标定 | mA → A，N*mm → N*m；A 不能直接当 N*m，不自动应用未提供的电机模型 |
| IMU | 角速度／线加速度字段、单位、轴系 | deg/s → rad/s、mm/s^2 → m/s^2；不自动去重力或旋转轴系 |
| 深度／点云 | 实际数值编码、比例、距离单位、坐标系、无效值约定 | 已声明的定形数值深度 mm → m；uint16 本身不证明毫米。点云数值可通过明确字段接入，不代表所有 ROS PointCloud2 编码已实现 |
| 触觉／接触 | 压力还是力、taxel 布局、标定、布尔事件语义 | 可保存／读取明确数值张量；未知原始码只做有限值等诊断。尚无通用压力单位及触觉专用质量检测验收，不能假装已转 SI |
| RGB／红外／视频 | 像素编码、相机角色、原图／原编码视频存储 | RGB 不需要换成物理长度；frames／video 按各通道实际存储路由。解码支持与某算法支持是两项验收 |
| 标定 | Home、容差、内外参、单位、坐标系与确认状态 | Home 和其容差同时等价换算；外参平移可转 m，内参中的像素不机械转 m；读取 SI 不自动校准 |
| 文本、标签、系统状态 | 文本／事件／数值角色和显式字段 | metadata／静态文本不按传感器频率评分；电量、温度、音频、GNSS 等仍需逐量声明与专门适配，不能以目录支持模态替代真实验收 |

例如一个通道的 position=deg、velocity=deg/s、effort=N*mm，要用 field_metadata 分别声明。
仅写通道 unit: rad 不能覆盖这三个不同物理量。混合六维 twist／wrench 也必须显式拆成字段／分量，
不要给整个数组一个统一单位。源读取保留 NaN、±Inf；SI 比例换算不填补这些异常。

通用比例换算的支持单位以 TRANSFORMS.md 为准。能读取并换算不代表已有相应质量方法：
例如目前 Numeric_Check 不会因此新增电流／力矩／触觉评分，也不会把相邻位置差解释成除以时间后的真实速度。
官方 LeRobot 对物理语义要求明确 quantity 和 semantic_status=confirmed；兼容后端保留旧配置规则，
明确 unknown／pending 会阻止物理读取，但缺省语义门槛尚未与官方后端完全一致，不能声称已统一完成。

## 时间单位、时钟映射与采样匹配是三步

1. 换单位：原时间 [1000, 1004] ms → [1, 1.004] s，只说明间隔 4 ms。
2. 换时钟：若有实测依据 t_camera = t_robot + 0.25 s，则机器人 [1, 1.004] s
   映射为相机时钟 [1.25, 1.254] s。没有共同 clock／映射就不能比较两路绝对时刻。
3. 匹配样本：相机 30 Hz、关节 250 Hz 保留各自频率。明确请求匹配时，按时间和容差找源行，
   保存源索引；不按行号对齐，不默认插值或把关节降到 30 Hz。

当前不会统一把所有传感器改为头部相机采样轴，也不能各减首帧后声称时钟已同步。
transforms.clocks 及 episode.transform_timestamps() 已有显式仿射时钟映射，
Projection_Alignment／显式 align_signal 会按其接口使用映射；
CPU Sync_Check／Root_Cause 等尚未通用自动消费 transforms.clocks，仍要求输入已具备可比较的共同 clock。
只填映射配置不会自动让这些算法变成可执行；也不能用相同 clock 标签替代真正映射后的时间值。

| 读取格式 | 时间如何进入算法 | 缺信息时怎么办 |
|---|---|---|
| ROS1／ROS2／ROS MCAP | 录制时间与各路有效 header.stamp 分开保留，整数 ns 留作证据；配置选择有效采集轴后转秒 | header 缺失／为零／条数不符，该路采集时间不可用，不回退录制时间替代；其他通道继续处理 |
| 非 ROS MCAP | 按编码和已实现读取器解释；不假装所有 schema 都有 ROS header | 未实现的原采集时间或消息解码明确缺输入／不支持；容器时间身份保持 container |
| HDF5 | 读取明确 timestamp_column；多候选拒绝猜选；明确单位后一次转秒 | 未知单位保留原值，可查时间相等，不能算物理时间间隔；多路独立时间的通用绑定尚未完整实现 |
| Parquet／轨迹 JSON | 指定原时间列与单位；仅一列时记 shared_dataset_rows | 公共行时间可以查本列间隔，不证明独立采集同步；只给 FPS 生成的时间保持 synthetic |
| 官方 LeRobot | 标准索引时间与 original_time 分开；补充配置恢复原值、单位、来源、clock | original_time 单位未知则不生成采集秒轴；共享原时间列不能伪装多路独立采集 |
| LeRobot 兼容读取 | 标准 timestamp 保留秒制索引身份；另选原时间列才使用原时间单位声明 | 标准索引时间不能通过配置升级为 acquisition；不替代官方后端验收 |
| MP4／派生视频 | 保留播放／合成时间，保存真实存在的源行映射 | 播放时间可以用于画面定位，不能证明原始采集同步 |

对未知时间单位，即使用户填写 time_source: acquisition 和 clock，也保留原始记录但不提供采集秒轴。
时间去重可比较精确原值，无须知道它是 ms 还是 ns；同步、采集间隔和需要速度／jerk 的算法不能如此绕过。
原始整数 ns 用于精确重复检查；大绝对时刻转 float64 秒仍有精度限制，
精密间隔／同步的统一相对基准尚未普遍接入，不把此限制隐藏为已验收。

## 阈值与验收

源 90 deg 进入算法时为 pi/2 rad。算法已经用 rad 的阈值保持原物理意义；不能再乘一次 pi/180。
用户标定若写 Home=90 deg、容差=3 deg，二者转换为 pi/2 rad 和约 0.05236 rad。
若旧算法本身采用非 SI 阈值，必须先核对其定义、作等价换算并测试；本轮没有擅自重设这些方法。

本轮合成测试覆盖 HDF5／Parquet／JSON 的未知与明确时间单位、ROS 时间边界既有回归、
官方 LeRobot 未确认原时间、数值精度、混合物理量、深度张量、四元数、布尔接触与字段语义。
这属于读取契约和回归验证，不是新增真实 X1 Pro／珞石质量检测结果，也不宣称所有传感器／编码均已接入。
