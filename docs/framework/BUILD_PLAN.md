# 建设计划

## 交付边界

框架名 Embodied Data Curation Framework，新库名 embodied-data-curation；兼容 embodied-dqs／dqs。首批公共核心＋9 项 CPU 质量方法，默认主流程质量→价值→可选增强；编辑生成副本后重检，增强后一致性与质量复检。

当前实现及测得结果见 [STATUS](STATUS.md)，操作见 [WORKFLOWS](WORKFLOWS.md)。计划不代表真实方法已完成验收。

## 三批交付

1. **私有基础仓库**：按当前工作区（含必要未跟踪文件）建立迁移清单；裁剪 CPU 包；基础安装不含 GPU、私有 wheel、权重或数据；独立安装、方法对照和贡献约束。
2. **统一示例闭环**：质量、显式编辑、重检、dataset 盘点、增强与复检；稳定数据引用、逻辑名/SI预检、只读上游、版本化放行、人工复核、精确恢复。
3. **真实方法逐项接入**：每次一个价值／编辑／增强方法，核对实际输入、环境、原输出、资源与许可。论文方案／GPU 方法不成为 CPU 基础包强依赖。

## 继续验收

- 第一批：方法源码与迁移基线逐文件一致；同输入同参数数值输出对照；源码外 wheel 安装。
- 第二批：失败和缺输入不放行；100 分待复核保留；左右/指令/反馈不互换；实际消费 SI 和显式 clock 映射；源只读、派生回读与追溯；恢复不复用已改变证据。
- 第三批：任务需求、相对已有数据的互补价值、使用后实际收益分别验证。一个抓取任务的恢复／效率需求属于候选研究验证，不是现有工程估值能力。

## 尚未完成的发布事项

GitHub 私有仓库创建需要有效 API 身份；本机只有原库 SSH 访问不足以创建新远端。仓库级代码许可、算法来源、第三方依赖、模型和真实样例分发范围逐项核查后再转公开。

平台可通过 catalog、记录和数据引用对接；本轮没有实现用户账号／权限、云端存储、多租户前端、启智平台集成或 VR 数据加速。增强示例不等于 Cosmos、VM 或任何特定加速方法。
