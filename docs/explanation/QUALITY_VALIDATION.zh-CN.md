# 从质量检查到自主数据整理

<a id="needs"></a>
## 用户需要什么，为什么检查

用户需要的是**适合目标任务与策略的数据，以及选择这些数据的依据**。需求包括任务与成功条件、目标策略与训练阶段、必需输入和质量要求、数据与计算预算；适用的方法还需要专家示教或可靠参考数据。当前通过[配置](../how-to/DATA_AND_ROBOT.zh-CN.md)表达输入与检查要求，获得报告、问题证据、[筛选数据副本或软链接及来源清单](../how-to/SELECTION.md)；后续将扩展到任务标注、模型相关的数据子集和改进版本。

**数据质量，指记录作为指定训练任务输入的可靠程度：必需信息完整，数值有效且含义、单位明确，观察与动作按约定正确对应。** 它关系到保存的数据能否可信地表达机器人看到了什么、做了什么，以及两者如何对应。示教完成与记录有效是不同属性。

必要条件是记录成为合格训练输入的前提。例如，抓取训练需要手部图像和关节动作：缺失必需图像，就没有要求的观察；动作值为 NaN，就没有有效动作目标；夹取前的画面错误配上松手动作，就表达了错误的观察—动作关系。

> 合格训练样本 → 满足必要条件；违反必要条件 → 不能直接视为合格训练样本。

EDC 将已支持的要求变成具体检查，定位问题并保留依据。必要条件取决于任务；静止画面不等于冻结，解码失败也可能来自读取环境，告警需要结合证据确认。**检查通过只说明满足本次已检查条件，不等于策略一定学得更好。**

<a id="layers"></a>
## 三层价值提供什么判断依据

**数据质量让机器能够正确读取与解释记录；任务价值把人对任务的理解转成学习信号；策略价值用模型反馈，连接人的目标与机器的学习方向。**

| 层次 | 判断的问题与依据 | 当前状态 |
|---|---|---|
| **Data-centric：数据质量** | 记录是否可信？将字段、数值和时间关系与明确的输入要求比较 | 已提供统一接入、九项 CPU 质量检查、证据记录和筛选导出 |
| **Task-aware：任务价值** | 什么操作经验值得学习？从专家示教和任务要求提取局部进展、关键操作及纠错信号 | 有研究基础，方法待接入 |
| **Policy-aware：策略价值** | 这些经验是否适合目标模型？利用模型学习反馈及可靠参考判断 | 有研究基础，方法待接入 |

跨机器人复用依靠配置与公共读取、预检接口：不同机器人映射各自的部件、字段和单位后，可复用检查方法；机器人语义、物理阈值和标定仍需分别确认。[支持范围](../reference/DATA_AND_ROBOTS.zh-CN.md#formats)说明具体条件。

任务价值关注经验包含什么可学内容，策略价值关注这些内容对指定模型是否有帮助。可靠数据的学习价值未必相同，失败轨迹也可能包含有用经验；这里的“对齐”通过选择和学习效果检验，不等同于模型已完整理解人的意图。

<a id="automation"></a>
## 为什么能够逐步自动化，并且有理有据

**从示教经验中学习怎样判断，从任务与模型反馈中检验判断效果，再据此改进数据选择。**

数据持续积累，任务与模型不断变化，逐条评估、逐轮选方法和调规则会重复消耗人工。自动化的可行性来自三个条件：**经验中的规律可学习，部分选择可由数据信号形成，候选方案的效果可比较。** 数据规模与多样性可能帮助建立这些能力，但效果取决于覆盖、参考可靠性和泛化，不能仅凭数据量推导。

| 需要替代的人工判断 | 自动化机制 | 研究支撑及边界 |
|---|---|---|
| 逐段判断任务是否取得进展 | 用专家示教帧对的归一化时间间隔构造自监督，学习局部进展与优势信号，再用于其他记录 | [STEAM](https://arxiv.org/html/2606.29834v2) 支撑可复用评估、减少逐帧标注；目标数据上的适用性仍需验证 |
| 判断数据是否适合目标模型 | 比较候选数据与语义、视觉匹配的干净参考样本的梯度相容性，汇总成轨迹分数 | [RoboDrop](https://arxiv.org/html/2609.10021v1) 提供模型相关的选择信号；相容性是代理，实际收益仍需训练验证 |
| 指定每批数据删除多少 | 从轨迹分数分布选择单高斯或双成分混合模型，再按低相容性群体和置信条件形成过滤决定 | [RoboDrop 第 4.5 节](https://arxiv.org/html/2609.10021v1#S4.SS5) 用 BIC 选择分布模型，可保留全部候选；无需预设删除比例，但仍有置信参数与建模假设 |
| 决定下一轮用什么算法、规则或处理方式 | 在质量与预算约束下比较可执行的候选方案，用验证反馈指导下一轮选择 | EDC 后续研究目标；上述论文没有直接验证完整自主决策过程 |

**经验形成评估能力，减少逐条人工判断；数据信号支持部分选择决策，减少人工指定筛选规则；进一步比较整理方案的实际效果，才可能逐步减少路线选择中的人工介入。** 相似性在这里帮助找到适合比较的参考，并非“越相似越值得保留”。

已有实验支持这些机制中的具体环节：

- **STEAM 与 CFGRL 结合**在四项真实机器人任务中的平均成功率为 **83.5%**，最佳基线为 **58.8%**，支持示教衍生信号用于策略学习。[论文实验](https://arxiv.org/html/2606.29834v2#S4)
- **RoboDrop** 报告整理后的真实机器人平均任务成功率由 **35.0% 提升至 67.5%**，支持模型相关信号用于数据选择。[论文实验](https://arxiv.org/html/2609.10021v1#S5.SS4)

以上为各论文实验条件下的结果；STEAM 的组合收益包含筛选以外的贡献。

<a id="evidence"></a>
### 有理有据：过程可追溯，判断可核验

- **过程可追溯**：知道使用了什么源数据、算法与参数，以及数据如何被保留或处理。
- **判断可核验**：知道依据与任务或模型有什么关系，并能通过独立复核和训练结果检验，而不只保留一个分数或日志。

拟议案例是“为抓取策略补充恢复经验”：用任务信号定位“抓偏—调整—成功”的候选片段，结合完整上下文判断，再用模型反馈评估学习价值；在可比预算下比较“仅成功轨迹”和“加入完整恢复片段”的训练效果。暂时倒退不直接等于无价值。这将**需求、信号、规则、数据去向与验证结果**关联起来，解释取舍并为下一轮调整提供依据。

<a id="autonomous"></a>
## 如何走向自主改进

**用户需求 → 标注与评估 → 选择或改进数据 → 获取任务与训练反馈 → 调整规则、算法与处理方式 → 再次评估。**

当前框架提供统一读取、[适用性推荐与执行](../how-to/RUN_AND_SELECT.zh-CN.md#selection)、证据记录和有限阶段工作流。推荐说明输入、参数与依赖是否满足，不表示已找到对用户目标最优的算法。工作流要求编辑／增强分支先校验来源与一致性，再重新质检，未达标不能放行；当前不支持任意片段调度或通用重采样变换。

价值方法将逐步接入。除上面的核心机制外，[FLORA](https://arxiv.org/abs/2610.31779) 提供结果、过程和带时间标记描述等自动标注的外部研究参考；MGT-QV 提供片段治理方向，DemoTempo 提供演示重采样与数据改进方向。MGT-QV 与 DemoTempo 的公开链接及实验结果尚未核实。

**长期目标是根据反馈比较并调整整理方案，让框架持续自主改进。** 用户确定目标、必要质量要求和预算，框架将探索在允许的候选算法、规则与处理方式中选择；进一步生成新算法，经验证后接入。每轮应保留方案版本、依据、成本和效果；必要质量要求不能为了提高保留率而自动放宽。上述研究分别支撑部分环节，完整自主决策与组合效果仍待实现和验证。

## 怎样验证这些优势

以下是待开展的验证，不是已有的完整框架实验结果。

| 要验证的主张 | 对应验证 |
|---|---|
| 评估能力可复用 | 在未用于学习评估器的数据上，与独立人工判断比较进度、分段和关键事件，检查任务与场景覆盖 |
| 自动化减少人工 | 在输出质量可比的前提下，记录人工工时、介入次数和计算成本 |
| 留下的记录更可靠 | 盲审抽样的原始、保留与剔除数据，比较缺陷比例及不确定性，检查是否误删困难或有用样本 |
| 筛选改善学习 | 比较原始全量、与 EDC 子集等量的随机子集、EDC 子集；逐层比较质量、任务价值和策略价值的贡献 |
| 反馈调整有效 | 后续比较固定方案与反馈调整方案，在可比总预算下记录任务表现与成本 |

训练对照固定策略、预处理和测试条件，使用多个随机种子及重复随机抽样，报告轨迹数、时长、成功率及波动。参考数据、评估器学习数据、规则调整数据与最终测试数据分开。优于等量随机组支持选择依据有用；还优于全量组，才能说明该实验中移除部分数据改善了学习。

完整框架的独立验证结合人工判断一致性、策略训练与任务表现。软件测试和重复质量检查验证实现行为，训练评估检验学习收益。
