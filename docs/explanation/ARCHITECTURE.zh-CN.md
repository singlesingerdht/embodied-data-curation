# 框架设计

[返回主页](../../README.zh-CN.md) · [English](ARCHITECTURE.md) · [说明区域](index.md)

EDC 通过统一数据模型、声明式配置、证据记录与插件接口组织数据整理流程。
具体操作见[操作指南](../how-to/index.md)；字段、参数与接口定义见[参考](../reference/index.md)；研究依据与验证边界见[从质量检查到自主数据整理](QUALITY_VALIDATION.zh-CN.md)。

## 统一执行管线

- **数据使用者**：提供数据与机器人配置 → 查看推荐并选择算法 → 运行、查看报告及导出数据。
- **算法开发者**：编写算法并声明输入输出 → 注册与验证 → 接入同一套推荐和执行流程。

内置算法与外部算法共用输入预检、执行与证据记录。公共 API 由 `edc` 导出；算法与读取器通过插件入口注册。

```text
src/edc/
├── data/          # 数据接口、读取器与变换
├── robots/        # 配置编译、部件与通道语义
├── algorithms/    # 注册、预检、九项质量算法与输出基类
├── execution/     # CLI、单次与批量执行
├── workflows/     # 可选阶段编排与复检接口
└── reporting/     # 报告与证据展示
```

## Dataset → Episode → Channel

一次采集往往包含多次操作；每次操作里又有各路关节、相机等记录。框架分别称为 **Dataset**（数据集）、**Episode**（一段操作）和 **Channel**（一路数据）。

轨迹边界以 metadata 或显式映射为准。稳定 ID、源文件与 selector 保证推荐、执行、报告和导出始终指向同一来源；轨迹数不由文件数推断。

## 四类配置

| 配置 | 回答什么 | 例子 |
|---|---|---|
| 数据集 | 这份集合包含哪些操作，边界在哪里 | `dataset.yaml`、LeRobot metadata、HDF5 组 |
| 机器人 YAML | 记录属于哪个部件、表示什么、什么单位 | `arms`、`cameras`、`data.time` |
| 算法参数 | 检查范围与阈值 | `checks.<算法ID>`、`arms: [left]` |
| 工作流 | 执行阶段与复检规则 | 质量、价值、编辑与增强阶段 |

总配置引用这四类子配置，并可导出为单份生效配置。

机器人配置声明部件，`checks.<方法>.arms` 选择本次检查范围；`all` 只展开声明为 arm 的部件，左右不会互相回退。同一机器人配置可用于多个任务；任务与 episode 信息属于数据集。换采集批次后，源字段、单位、标定及 clock 的适用范围仍须重新核对。

## 单位与时间来源

已确认的物理字段只在**官方执行器提供的算法上下文**中按 SI 读取；原始数组保持不变。未知单位保留为未知，不能用无量纲 `1` 代替，也不能靠归一化推断。普通 `open_dataset()` 的源读取视图不保证是 SI 数值视图，插件应使用执行器传入的 episode。

时间区分 acquisition（采集）、container（容器记录）、playback（播放）、synthetic（生成）和 unknown。跨通道比较必须有共同 clock 或显式映射；文件格式、共享行时间或选定的参考相机都不能单独证明采集同步。

## 结果语义与证据

一次运行里，处理状态与数据判断分开：

- 处理状态说明是否执行、是否适用；
- 数据判断使用通过、复核、可救、排除；
- 未检查、不适用或执行失败不能写成通过；
- 每项保留原始指标、事件、源行与证据，不生成跨算法或跨臂总分。

证据支持后续复核与导出。通过仅表示满足已检查条件；策略学习收益须通过训练验证。运行输出由 `catalog.json` 发现，`_runs/<run_id>` 保存配置、版本、记录、错误与证据；工作流另存完整生效配置与来源指纹。历史证据保持不变。

## 有限阶段工作流

工作流使用 SI 执行输入、算法注册、适用性检查与原始结果，编排显式、有限的阶段列表。编辑与增强生成的新版本须先通过一致性与来源校验，再复检质量；未通过校验或质量要求时挂起。价值、编辑和增强阶段可省略，恢复执行仍遵循有限计划。

## 扩展点

新算法通过 `edc.algorithms` 使用 `AlgorithmSpec` 与 `run(context, params)` 注册；新格式通过 `edc.readers` 接入。外部 ID 使用 `team__algorithm`，重复 ID 或不兼容接口版本明确失败；模型与 GPU 依赖按需加载。

具体写法见[算法扩展](../how-to/ALGORITHM_PLUGIN.zh-CN.md)与[读取器扩展](../how-to/READER_PLUGIN.zh-CN.md)；对象定义见[接口与输出参考](../reference/OUTPUTS.zh-CN.md)。

## 明确的边界

- 结构检查不证明物理语义、任务成功或传感器健康。
- 推荐只说明输入条件，不表示已找到对用户目标最优的算法。
- 处理失败记录为错误，不赋予质量判断。
- 任务价值与策略价值方法仍在接入中；当前提供的是数据质量检查、证据记录和筛选导出。
