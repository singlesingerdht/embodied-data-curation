# 动作平滑度（Action_Smoothness）

查末端（手）在不在抖。每条手臂单独出一项结论。

## 输入

- 末端位置（米）：数据里录了就直接用（yaml `eef_position`），没录就由关节角经 URDF 算（`eef_position: fk`）。
- 这条通道自己的时间：采集时间、容器时间，或格式规定的帧时间（LeRobot 的“帧号 ÷ 帧率”）。

## 方法（`method.py`）

1. **分出抖动。** 末端轨迹里每秒来回少于 2 次的部分是有意动作；2 次到上限之间的部分算抖动。上限 = min(10, 0.4 × 采样率)：采样 25 Hz 以上查 2–10 Hz，20 Hz 查 2–8 Hz，15 Hz 查 2–6 Hz。频段按赫兹定，所以结果不随采样率变；采样率低于 10 Hz 记“不适用”。
2. **抖动加速度**（米/秒²，1 米/秒² 约 0.1 g）：抖动部分求两次导数。滤波和求导一起在频域做，零相位、不产生时间延迟。
3. **停住 / 运动。** 有意动作的速度低于 1 厘米/秒、持续 0.3 秒以上算停住，其余算运动。
4. **结论只看停住段。** 停住段抖动加速度的均方根超过复核线 → 复核，报告写出数值和最抖的时刻（0.5 秒窗口）。运动段同样算出数值，只列出来参考：快速伸手、急停、撒盐这类正常动作本身也落在这个频段（0.5 秒内伸出 20 厘米就有 4–5 米/秒²），在运动中分不清是动作利落还是抖。
5. **读数冻结。** 位置连续 1 秒以上完全不变，而冻结前 0.1 秒还在以 5 厘米/秒以上移动：读数中途停更，复核。正常停下会先减速，不算。
6. 只有通过、复核、不适用三种结论，本算法不排除。手没停住过、也没有冻结时，记不适用。

时间断档（间隔超过中位间隔 3 倍、且超过最短抖动周期的一半）处分开算；每段先放到等间隔网格（就用它自己的中位间隔，不升采样），两端各舍 0.5 秒。NaN 行当作断档。

## 参数（机型 yaml 的 `checks.Action_Smoothness`，只写要改的）

| 参数 | 默认 | 含义 |
|---|---|---|
| `still_review_m_s2` | 1.0 | 停住时的复核线 |
| `band_hz` | [2, 10] | 抖动的频率范围 |
| `band_rate_ratio` | 0.4 | 上限最多取采样率的这个倍数 |
| `min_rate_hz` | 10 | 低于它不检查 |
| `still_speed_m_s` / `still_min_s` | 0.01 / 0.3 | 停住的判定 |
| `freeze_min_s` / `freeze_speed_m_s` | 1 / 0.05 | 读数冻结的判定 |

默认值都在 `method.py` 的 `DEFAULTS` 一处。

## 阈值含义与适用限制

默认停住复核线为 1.0 米/秒²，约相当于 6 Hz、振幅 0.7 毫米的正弦抖动。该阈值是可配置的检测条件，尚未经过人工标注校准，不应视为所有机器人与任务的通用合格标准。

运动中的加速度可能来自有意动作，因此仅展示运动段数值，不据此判定质量。用于新设备或任务时，应以代表性数据和独立标注检查误报、漏报及阈值适用性；采样率、时间断档和停住条件仍须满足上述输入要求。
