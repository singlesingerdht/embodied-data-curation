# Reset_Detection 方法讲解（配图版）

> 讲解顺序建议：先讲"要解决什么问题"→ 两阶段流程（图1）→ 单参数怎么打分（图2）→ 一条数据怎么检（图3）→ 多参数怎么聚合/熔断（图4）→ 输出什么。

---

## 0. 一句话定位

**检测机器人在 Episode 开始时和结束时是否都处于"原位"（Home Position）。**

- 开始不在原位 → **Init（初始化）不合格**：数据采集起点就有问题
- 结束没回原位 → **Reset（复位）不合格**：这条轨迹的终止状态不可用

为什么重要：模仿学习数据集里，每条轨迹的**初始状态分布**和**终止状态分布**都会被模型学到。初始/终止状态乱了，等于给模型喂脏数据。

---

## 1. 整体流程：校准 + 检测 两阶段（图1）

![整体流程](figures/fig1_pipeline.png)

### 阶段一：校准（离线，做一次）

核心思想：**"原位是什么样、允许多大偏差"不是拍脑袋定的，而是从一批正常数据里统计出来的。**

1. 取一批正常 Episodes（如 50 条）
2. 逐条抽取**首帧**数值（每个参数：末端位置、关节角、夹爪……）
3. 对每个参数统计 `mean` 和 `std`
4. 生成三样东西，写入 `calibrated.yaml`：

| 产物 | 公式 | 含义 |
|---|---|---|
| `home_position` | `mean` | 原位参考值 |
| `tolerance1` | `2σ` | **满分边界**：偏差在此以内 → 100 分 |
| `tolerance2` | `3σ` | **零分边界**：偏差超出此值 → 0 分（熔断） |

> 讲解要点：这套配置**完全可手写覆盖**。`calibrated.yaml` 里每个参数有 `type / calibrate / detect` 三个开关——type 决定误差算法（scalar/vector/quaternion），calibrate 决定是否参与统计，detect 决定是否参与评分。有厂家标定值可以直接手写 home 和阈值，跳过校准。

### 阶段二：检测（逐条 Episode）

对每条 Episode 做**两次独立评估**（同一套 home 与阈值）：

- **Init 评估**：取**首帧**，逐参数算误差、打分
- **Reset 评估**：取**末帧**，同样流程

> 讲解要点：**只看首帧和末帧，中间的运动过程完全不参与打分**。算法不关心任务怎么执行，只关心"起点对不对、终点回没回"。

## 2. 单参数打分：双阈值线性插值（图2）

![评分曲线](figures/fig2_score_curve.png)

误差定义（按参数类型）：

| 类型 | 误差 | 说明 |
|---|---|---|
| scalar | `|当前值 - home|` | 如夹爪开合度 |
| vector | 逐维 `\|差\|`，逐维打分 | 如末端 xyz、关节角向量 |
| quaternion | `2·arccos(\|dot(q1,q2)\|)` | 姿态角差（弧度） |

打分公式：

```
score = 100                    ,  error ≤ tolerance1 (2σ)
score = 100 × (t2 - e)/(t2 - t1) ,  tolerance1 < error < tolerance2
score = 0                      ,  error ≥ tolerance2 (3σ)
```

图2 上三个示例点（对应讲解）：

- 误差 8mm（≤2σ=20mm）→ **100 分**，绿色区，满分
- 误差 28.4mm（2σ~3σ 之间）→ **72 分**，黄色区，线性扣分
- 误差 55mm（≥3σ=50mm）→ **0 分**，红色区，**熔断**

> 讲解要点：不是"过/不过"的硬门槛，而是 2σ 到 3σ 之间**平滑过渡**——轻微偏移扣少量分，严重偏移直接归零。vector 类型**逐维独立打分**，任一维 0 分则该参数整体 0 分（一只手指没复位 = 手没复位）。

## 3. 一条 Episode 的检测实例（图3）

![Episode 检测](figures/fig3_episode.png)

图3 上图：末端位置随时间的轨迹（纵轴是偏离原位的距离，三条彩色横带是阈值带）

- **首帧**（绿点）：误差 5mm，落在绿色满分带 → Init 该参数 **100 分**
- 任务过程：轨迹大幅运动，穿过熔断带——**不影响打分**
- **末帧**（橙点）：误差 28.4mm，落在黄色线性带 → Reset 该参数 **72 分**

图3 下图：把首末帧误差映射到评分曲线上，直观看到 5→100、28.4→72 的对应关系。

> 讲解要点：这张图最能打消常见误解——"中间超阈值不算失败吗？"不算。复位检测只约束**两端状态**，中间怎么动是任务本身的事，由其他算法模块（如动作平滑性）去评。

## 4. 三层聚合与熔断（图4）

![聚合与熔断](figures/fig4_aggregation.png)

### 聚合链路（图4 左，正常示例：3 个 detect 参数）

```
参数分:  Init [100, 100, 100]          Reset [72, 100, 100]
              ↓ mean                        ↓ mean
评估分:  Init = 100 (passed)           Reset = 90.7 (passed)
              └──────────┬──────────────────┘
                         ↓ min
模块分:  min(100, 90.7) = 90.7 → A 级 → ACCEPTABLE
```

### 熔断示例（图4 右）

Reset 评估中底盘误差 55mm ≥ 3σ → 底盘 0 分 → **Reset 评估熔断为 0**（即使另外两个参数都是满分）→ 模块分 = min(100, 0) = **0 → DO_NOT_USE**

### 规则总结

| 层级 | 规则 | 设计动机 |
|---|---|---|
| 参数 → 评估 | `mean(参数分)`；**任一参数 0 分 → 评估熔断为 0** | 一个部件飞了，整次复位就没意义 |
| 评估 → 模块 | `min(Init, Reset)`；任一熔断 → 模块 0 分 | 起点对不能弥补终点没回，反之亦然 |
| verdict | 熔断 → `DO_NOT_USE`；score<85 → `NEEDS_REVIEW`；否则 `ACCEPTABLE` | 三态输出，供下游融合 |

> 讲解要点：min 聚合 = "两者都得对，不让好的拉高差的"。这是和平均聚合的本质区别——一条 Init=100 但 Reset=0 的数据，平均会给 50 分（看似及格），min 给 0 分（正确拒绝）。

## 5. 输出：统一契约 JSON

每条 Episode 一份单对象报告（与 A/B/C/yjy/projection_alignment 同构，可被 `shared/fusion.py` 融合）：

```json
{
  "module": "reset_detection",
  "score": 90.7,
  "grade": "A",
  "verdict": "ACCEPTABLE",
  "reasons": ["[Reset] 左臂末端位置未完全回到初始状态（72分）"],
  "attribution": [
    {"sub_indicator": "Reset", "atom": "左臂末端位置", "score": 72.0,
     "gap": 28.0, "weighted_gap": 14.0, "val": 0.0284, "t_min": 0.02, "t_max": 0.05}
  ],
  "sub_indicators": [
    {"name": "Initialization", "score": 100, "grade": "S", "passed": true, "details": [...]},
    {"name": "Reset",          "score": 90.7, "grade": "A", "passed": true, "details": [...]}
  ],
  "threshold_profile": {"tolerance1_factor": "2σ", "tolerance2_factor": "3σ",
                        "aggregate": "min(Init,Reset), any-melt→DO_NOT_USE"}
}
```

三层归因信息：

- `sub_indicators[].details` — 每个参数的原子分（审计粒度最细）
- `attribution` — **扣分账单**：只列 gap>0 的参数，按 weighted_gap 降序，机器可读
- `reasons` — 自然语言归因，带 `[Init]/[Reset]` 前缀，人读

## 7. 可能被问到的 Q&A（讲解备弹）

**Q: 为什么用首帧统计做校准，而不是全帧？**
A: 校准的目标是学"原位"，原位只出现在每条数据的起点。用全帧统计会把任务中的运动也平均进去，home 就不再是原位了。

**Q: σ 是跨 Episode 的还是 Episode 内的？**
A: 跨 Episode——50 条数据首帧值分布的标准差。它反映的是"正常采集下起点的自然波动"。

**Q: 阈值会不会太松/太紧？**
A: 可调。改 `tolerance1_factor / tolerance2_factor` 重新校准即可；校准时若某参数 std 异常大（>1）会打 WARNING，提示可能是多模态分布，用 `exclude_episodes` 排除异常数据。

**Q: 一条数据只有 Init 坏，Reset 好，会怎样？**
A: min 聚合 → 模块分取 Init 的低分；若 Init 熔断则整条 DO_NOT_USE。

**Q: 手动指定原位行不行？**
A: 行。直接编辑 `calibrated.yaml` 写 `home_position / tolerance1 / tolerance2`，代码不区分是校准生成的还是手写的。
