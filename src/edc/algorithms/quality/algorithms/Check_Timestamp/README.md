# 时间戳对齐（Check_Timestamp）

## 检查什么

以头部彩色相机为基准，看每一路数据（其他相机、关节、末端、夹爪等）能不能按采集时间和头部画面一一配上，以及每一路自己的消息是不是按固定节奏到达。

- **能不能配上**：对头部的每一帧，找这一路里时间最近的一条，看有多少帧找得到、差了多少毫秒、是不是整体早或晚一截、差值是不是忽大忽小、是不是越走越偏。
- **节奏稳不稳**：这一路相邻两条消息的间隔是否稳定，有没有中途断开（间隔超过平时的 2 倍且超过 20 毫秒）。
- **时间段是否重合**：这一路和头部的录制时间段重合够不够。
- **头部自己**：不和自己比，只查节奏；头部时间倒退、重复或算不出采样周期时不能当基准，整项排除。

只用采集时间（消息头里的时间），不用录包时间；录包时间由采集同步（Sync_Check）查。

## 怎么打分

1. 选参考：彩色相机里优先选头部（话题名含 head 且含 rgb/color），其次 front / cam_h。
2. 头部一行：只看节奏打分，只扣分不加分——低于其他路的平均分才计入平均；报告写“参考相机自身节奏不稳”。
3. 其他每一路：得分 = 对齐 × 权重 + 节奏 × 权重（相机 0.9 / 0.1，数据话题 0.7 / 0.3）。
   - 对齐：配上比例 20%、P50 误差 20%、P99 误差 25%、整体偏移 10%、残余抖动 15%、漂移 10%。误差阈值按帧间隔缩放，数据话题按自己的间隔算，更严。
   - 节奏：间隔波动系数 65%、长间隔比例 35%（长间隔次数 ÷ 间隔总数）。
   - 和头部的时间段重合低于 95%：每少 1 个百分点扣 2 分；完全不重合记 0 分。
4. 整条：计入的各行的平均分，高于 90 通过，80–90 复核，80 及以下排除。

所有数据共用一条行时间（JSON、LeRobot 等）时不走上面的打分，只查跳帧，见 `algorithm.py`。

## 代码

- `run_check.py`：`assess_from_ir` 是框架调用的入口；`score_reference` 给头部打分，`score_topic` 给其他每一路打分。阈值常量在文件开头（`DEFAULT_*`），各机型统一的覆盖值（间隔波动 0.3 起扣、0.6 扣满，误差下限为最快彩色相机帧间隔的 1/3）在 `algorithm.py`。
- `result.py`：把结果写成报告里的中文句子。
