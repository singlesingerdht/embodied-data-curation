# 时间戳对齐（Check_Timestamp）

框架通过 `run_check.assess_from_ir(info, reader)` 调用，没有单独的命令行；用 `edc run --algorithm Check_Timestamp` 或 `edc batch` 跑。`result.py` 把结果写成报告里的中文句子。

## 怎么算

1. **选参考**：在彩色相机里优先选头部（话题名含 head 且含 rgb/color），其次 front / cam_h。
2. **参考相机自己**：不和自己比，只按节奏打一行分，计入平均；报告写“参考相机自身节奏不稳”。时间倒退、重复或算不出采样周期时不能当基准，整项 0 分（排除）。
3. **其他每一路**：对参考的每一帧找时间上最近的一条，得分 = 对齐 × 权重 + 节奏 × 权重（相机 0.9 / 0.1，数据话题 0.7 / 0.3）。
   - 对齐（满分 100）：配上比例 20%、P50 误差 20%、P99 误差 25%、整体偏移 10%、残余抖动 15%、漂移 10%。误差阈值按帧间隔缩放，数据话题按自己的间隔算，更严。
   - 节奏（满分 100）：间隔波动系数 65%、长间隔比例 35%（长间隔 = 超过中位间隔 2 倍且超过 20 毫秒；比例 = 长间隔次数 ÷ 间隔总数）。
   - 和参考的时间段重合低于 95%：每少 1 个百分点扣 2 分；完全不重合记 0 分。
4. **整条**：所有行的平均分，高于 90 通过，80–90 复核，80 及以下排除。

所有数据共用一条行时间（JSON、LeRobot 等）时走适配层的简化检查，只查跳帧，见 `adapters/cpu.py`。

阈值常量在 `run_check.py` 开头（`DEFAULT_*`）；各机型统一的覆盖值（间隔波动 0.3 起扣、0.6 扣满，误差下限为最快彩色相机帧间隔的 1/3）在 `adapters/cpu.py`。
